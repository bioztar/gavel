Room
Humans in the call
Discord voice channel + browser pages (join, watch, stage projector view)
↕ Discord voice · browser HTTP/SSE/WebRTC
gavel runtime — our containers (compose.yaml)
Traefik
Ingress + TLS. Routes /console (off by default, basic-auth), calendar's host, /karen-video·/stage·/director, /watch·/stream/status.
ears-discord
Stenographer. Owns the Discord voice connection, transcribes, records, plays audio back. Makes no decisions.
brain — Karen
The chair. Tracks the floor, keeps the agenda, decides, writes the line, speaks it.
calendar
.ics invite → agenda. Serves the join page that opens the demo.
chair-video
Lip-synced talking head. Drives the projector's live Director feed. No decisions.
stream-vonage
HLS restream + archive of the stage, alongside Discord — never instead of it.
Postgres / Redis
Postgres: transcripts + sessions. Redis: ears' own frame stream + pub/sub, a second door.
↕ HTTP · WebSocket wire · SSE · queue APIs
Third-party AI services — runtime
SLNG
Speech: STT (ears transcribes each speaker) + TTS (the chair's voice and the console say-box).
Nebius
Model inference. Two independent consumers: the chair (via Mastra agents) and calendar's brief parser.
Mastra
Backend orchestration inside brain: chair / relevance / digest agents, the intervene workflow.
fal
Queue-API lip-sync + avatar render, called by chair-video. Feeds the Director WebRTC stage.
Vonage
Video API: session, HLS broadcast, archive of the live stage — via stream-vonage.

Runtime wiring — what talks to what, over what

Humans ↔ ears-discord Discord voice
ears-discord ↔ brain WebSocket wire: frames out, speak/stop in
ears-discord → SLNG HTTP: STT per utterance, TTS say-box
brain → SLNG HTTP: the chair's spoken line
brain → Nebius HTTPS, via Mastra agents
brain ⇢ chair-video HTTP, best-effort, 2s abort, fire-and-forget
calendar → Nebius HTTP: free-text brief → agenda JSON
calendar → ears-discord HTTP: seed / join session
chair-video → fal HTTP: queue lip-sync + avatar jobs
chair-video → Humans SSE (/director/events) + browser WebRTC
stream-vonage → brain HTTP poll: GET /state
stream-vonage ↔ Vonage HTTPS/JWT: session, broadcast, archive
Humans (publisher page) → Vonage getDisplayMedia → WebRTC publish
ears-discord ↔ Postgres / Redis persist transcripts, fan out frames
Traefik → calendar / chair-video / stream-vonage HTTPS ingress, TLS
